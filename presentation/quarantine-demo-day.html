Quarantine

The offline clean room for untrusted model artifacts.

Every model you download is code you did not write. Quarantine runs it where it cannot hurt you, records what it does, has a local open-weight model read that behaviour against the artifact's own declaration, blocks what it cannot explain, and repairs what it can — with a signed receipt at the end.

01 The problem

A model artifact is not data. It is code: a pickle, a custom modeling_*.py, a config that says trust_remote_code=True. Loading it runs somebody else's code with your credentials, in your network, on your machine.

What the scanners do

  • match names against a denylist of dangerous globals
  • read pickle opcodes — never a .py file
  • say clean or suspicious, and stop there

What they cannot do

  • see the code path: custom_generate/, modeling_*.py
  • tell you what the artifact did
  • give you anything to ship afterwards

Measured on our labeled corpus: picklescan 2/9, fickling 2/9 — and both are clean on the seven payloads that live in the code path.

02 The insight

Judge what the artifact did, against what it declared — in a box where doing it is harmless.

  • Containment is not a safety net around the analysis; it is the analysis. Behaviour is the ground truth, and it is the one thing a name-matching scanner cannot see.
  • The AI decides what the evidence means. Code decides what was observed — so no verdict rests on a model's opinion of its own work.
  • "We could not look" is a first-class outcome. It is never reported as "fine".

"We could not run it, so we saw nothing, so it is fine" is the most dangerous default a security gate can have. The first version of this tool did exactly that.

03 An agent team, not a pipeline

Six roles. Three use the local model, three are deterministic code. They never call each other: each posts to an append-only case file and the supervisor routes from what is on it.

observerdeterministicexecute it contained, network off, record every sensitive operation

challengerAIrefute the analyst — only by quoting the declaration verbatim

Routing is a policy, not a prompt — including the three branches that exist to avoid saying "fine" when we did not look.

They win on their corpus, and here is why. Their payloads mostly name a vulnerable entry point in a host library (cProfile.run, pty.spawn, torch.utils.collect_env.run) and call nothing when loaded alone — so there is no behaviour to observe. Ours act on load.

So this is not a replacement for a pickle scanner. It is the other half of the pair — and the half that opens the .py files, and repairs what it blocks.

06 The repair is proven, not asserted

A block with no path forward is just a complaint. So the blocked artifact is repaired, and the repair is proven by a deterministic verifier.

  • identical outputs on 12 prompts (case, punctuation, unicode, empty string, whitespace, tab, digits, newline, 300-character input)
  • and zero capability operations while doing it — measured from the trace, not read off the source

On the reference artifact the original performed 2 capability operations (file.read /etc/hostname, socket.getaddrinfo); the repair performed 0.

Across the corpus: 9/9 blocked · 7 repairs attempted · 7/7 capability-clean · 6/7 verified. The seventh is a refusal, not a failure — the original cannot be executed at all, so equivalence with it cannot be established, and the receipt says so.

The verifier imports nothing from this project and no third-party package, and checks the Ed25519 signature with OpenSSL — a different implementation than the one that signed it.

Flip the verdict from BLOCK to ALLOW in the JSON and it says NOT VERIFIED. That was tested, both ways.

08 Pointed at Nepal

268 Nepali/Indic repositories searched for the risk that matters most — models that force trust_remote_code=True: 46 ship .py files, 15 declare auto_map. Neither incumbent scanner opens a .py file at all.

What it found

  • a Nepali voice engine (740 downloads) with a custom architecture
  • a Nepali-tuned Qwen shipped as GGUF — and our reader did not know the format the community actually distributes in
  • two real models exposed two defects in our own tool

What it costs us

  • remote-code models escalate, because their modeling_*.py needs torch and we will not judge a code path we never ran
  • the image that fixes it measured worse (40% false positives) and ships off by default

09 Twenty-seven defects, found by running it

Every one was found by a control group, a third-party artifact, a rate or a corpus — never by the case being demonstrated.

The ones that matter most

  • an artifact that could not run was reported ALLOW
  • the challenger overturned a correct BLOCK by asserting, with real trace ids, that the declaration permitted a DNS lookup → a refutation must now quote the declaration
  • a BLOCK grounded by citing an error — blocked a benign published model
  • re.compile is not the builtin compile; the pickle protocol emits builtins.getattr itself

And the negative results

  • 19 probes for callables both scanners miss: no gap found, so no bypass is claimed
  • the torch image: built, measured, turned off
  • 10 breakout primitives: 0 escaped

10 Why it is a business

  • The constraint is the product. Local open-weight model, no API key, no vendor account, no bandwidth. It is the only scanner that can be pointed at a customer's private registry or run air-gapped — where cloud scanners are structurally excluded.
  • Free tools cannot do this. The incumbents are static; hosting and containment, signed evidence an auditor will accept, and a repair you can ship are what a buyer pays for.
  • Beachhead: Nepal and South Asia. Closest design partners, cheapest GTM, and a deployment reality (intermittent bandwidth, data residency) this architecture already fits.
  • IP, honestly. Apache-2.0 core; the defensible assets are the labeled corpus, the receipt format as an adopted standard, and the deterministic admissibility rule.

A full proposal — market, pricing, unit economics, regional GTM, IP position, and a list of what is not verified — accompanies this submission.

The organisers publish a minimum-requirement list and a list of what counts as AI usage. Both are quoted and mapped, one by one, in docs/EVENT-REQUIREMENTS.md — including their four disqualifiers, each structurally absent here.

Their guidance: "financial support or API keys will not be provided" — so the model runs locally. "Only open-source or open-weight AI" — we are stricter, self-hosted only, and the model layer is one function so a buyer can point it at their own endpoint.

12 What we are not claiming

  • Nineteen limitations. LIMITATIONS.md carries the items that flatter the numbers least: 47% on their corpus, the torch image that made things worse, and the analyst's run-to-run citation variance.
  • No scanner bypass. We looked for one and published the negative result.
  • No proof the box cannot be broken. Ten primitives failed; that is a measurement, not a guarantee.
  • Poisoned weights are out of scope. We validate containers; we do not judge tensor values.
  • The corpus is ours. Which is why the third-party controls and the Nepali models exist — and why we say so on the same slide as the 9/9.

A gate that hides its failure modes is not a gate. Everything above is reproducible with scripts in the repository.
